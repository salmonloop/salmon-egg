# 左侧导航栏按会话状态分组

状态：已进入开发与门禁验证阶段；焦点行暂留位置、离开后归组的交互已于 2026-09-12 获用户确认。原生祖先分组指示问题仍在处理，尚未完成交付。本文仅保存在本地，不提交；后续安排见 [开发计划](PLAN-SESSION-STATUS-NAVIGATION.md)。

## 1. 目标

在现有「按项目」组织方式之外，增加「按状态」视图，让用户跨项目查看哪些会话需要自己处理、哪些仍在运行。

按状态时只保留三个分组，顺序固定：**待处理 → 进行中 → 其他会话**。会话行通过图标表达具体原因，不增加常驻的原因文字。

这是一种会话导航方式，不是任务看板；不提供手动拖动状态、标记任务完成或新的归档流程。

## 2. 设置与切换

| 项目 | 要求 |
| --- | --- |
| 设置位置 | 设置 → 外观 → 侧栏会话分组 |
| 选项 | 按项目、按状态 |
| 默认值 | 按项目，保留现有使用习惯 |
| 保存 | 记住选择，下次启动沿用 |
| 数据范围 | 使用现有侧栏收录的会话；切换组织方式不改变项目归属、归档状态或会话身份 |
| 生效方式 | 优先直接切换。允许需要重载后生效，具体方式由后续技术调研决定 |

切换组织方式应保留当前会话、正文、草稿和正在执行的工作。若确实需要重启程序，应明确提示生效方式并允许稍后生效，不自动打断正在运行的会话。

## 3. 分组规则

### 3.1 分组含义

| 分组 | 收录条件 |
| --- | --- |
| 待处理 | 已结束的本轮回复尚未读过；或存在仍有效的授权、回答请求；或存在当前需要用户介入的问题 |
| 进行中 | 本会话仍在发送、等待 Agent、思考、执行工具或流式回复，且没有更优先的待处理事项 |
| 其他会话 | 没有上述事项，包括回复已读、尚未开始、主动停止，以及当前状态无法确认的会话 |

每个会话只出现一次。「已回复」不再单独成组；未读回复进入待处理，已读且没有其他待办事项的会话进入其他会话。

### 3.2 判定优先级

按最新、仍有效的会话事实依次判定：

1. 有待用户响应的授权、提问，或阻止继续工作的可操作问题：待处理。
2. 本轮仍在运行：进行中，即使已经产生未读的流式片段。
3. 本轮已结束，且有未读回复：待处理。
4. 其余情况：其他会话。

工具排队不等于等待用户。Agent 能自行恢复的单次工具失败，也不应立即把整个会话变成待处理。

打开会话不等于解决授权、提问或错误。只有对应事项确实解决、取消或失效，才解除该项待处理原因；随后根据其余事实重新归组。

### 3.3 典型流转

| 事件 | 结果 |
| --- | --- |
| 用户开始新一轮对话 | 进入进行中 |
| 运行中收到授权或结构化提问 | 进入待处理 |
| 用户完成响应，Agent 继续工作 | 返回进行中 |
| 回复结束，最新结果尚未读过 | 进入待处理 |
| 最新回复已读，且没有其他待处理事项 | 进入其他会话 |
| 回复结束时，用户已在前台看到最新结果 | 直接进入其他会话，不短暂闪入待处理 |
| 当前工作发生需要用户恢复的故障 | 进入待处理 |
| 用户主动停止，且没有其余待处理事项 | 进入其他会话 |

取消、拒绝、达到限制和失败不能被当作任务成功完成。各类非正常结束与未读结果的具体组合，留待技术调研结合可靠事实细化。

## 4. 图标与文字

会话左侧的图标承担状态提示。标题、项目名和正常的时间信息可以显示；不在行内增加「等待批准」「新回复」「需要重试」等原因文字，也不增加状态文字徽章。

| 情况 | 图标语义 | 悬停与读屏说明示例 |
| --- | --- | --- |
| 已回复但未读 | 带未读点的对话图标 | 新回复，未读 |
| 等待授权 | 盾牌 | 等待批准 |
| 等待回答 | 问号气泡 | 需要回答 |
| 需要处理的错误 | 警告图标 | 需要处理的问题；具体操作由实际错误决定 |
| 正在运行 | 原生进度指示 | 正在运行 |
| 其他会话 | 普通会话图标 | 根据事实说明已读、尚未开始、已停止或状态未知 |

图标采用现有原生图标与控件体系，保持系统主题和尺寸习惯。具体字形在技术调研中确认，不把示意符号或 emoji 当作交付图标。

每行只显示一个主状态图标，未读点不重复绘制。阻塞处理图标优先于运行和普通未读；多个待处理原因并存时，具体图标优先级在后续调研中提出明确方案。

颜色只作辅助，图形本身必须可区分。悬停提示与读屏名称应说明含义；触控用户进入会话后能找到实际回复、请求或问题，操作不能依赖悬停。

## 5. 已读语义

「已读」表示最新回复已实际显示在用户正在使用的前台窗口中。仅选中导航项、后台加载完成、窗口最小化，或仍停留在未显示最新回复的旧消息位置，都不能单独作为已读依据。

具体要求：

- 读取回复只清除对应内容的未读，不消除未解决的授权、提问或错误。
- 本次阅读不能清除同时到达但尚未显示的新内容。
- 运行中的未读片段不会使会话提前进入待处理；本轮结束后再按阅读情况归组。
- 已读后发生新的待处理事项，会话重新进入待处理。

如何取得可靠的前台与内容可见事实，由技术调研决定；产品不要求猜测用户视线或设置固定阅读倒计时。

## 6. 侧栏结构与交互

按状态时采用「状态分组 → 会话」两层结构，跨项目直接列出会话，不再嵌套项目层。会话标题下保留项目简称；仅在需要区分来源时补充 Agent 名称。

以下默认交互随本文一并审阅：

- 三个分组标题保持固定顺序并显示数量；空组保留标题和零计数。
- 待处理、进行中默认展开，其他会话默认折叠；记住用户的展开选择，新消息不强行展开分组。
- 数量表示该组已收录的会话总数，包含折叠或渐进显示中暂不可见的会话，不表示远端全部会话数量。
- 组内按最近有效活动排序；流式片段不持续推动行重排。大量会话仍可通过原有导航方式访问。
- 分组更新不能切换右侧正文、清空草稿、重复激活会话或抢走焦点。
- 用户正点击或用键盘导航时，不突然将目标行替换成另一会话。焦点所在会话暂留原组、状态图标及时更新；所在组保留已显示行的顺序，其他分组继续更新。焦点离开该会话后立即按最新状态归组，不等待鼠标离开侧栏。（此交互已由用户于 2026-09-12 确认。）
- 当前会话换组后仍保持同一身份和选中关系；即使目标组折叠，也不能使当前会话失联或丢失定位线索。
- 新建会话仍明确选择所属项目；按状态组织不改变新建、搜索、发现、归档等入口的业务含义。

## 7. 状态可信度与 ACP 边界

以下边界来自前期产品讨论已经核对的 ACP 资料；进一步的源码与框架依据记录在开发计划中。

- 「未读／已读」是客户端的阅读状态，不是 ACP 的任务完成标记。
- 稳定版 ACP 的一轮回复结束不等于整个任务已完成。计划条目、单个工具的状态也不能直接当作整个会话状态。
- 会话列表只提供发现信息，不能根据更新时间、存在历史记录或连接成功就推断会话正在工作或已经回复。
- ACP v2 草案已有运行、空闲、需要操作等状态，但空闲时仍可能有后台工作。本功能不得以启用未完成的草案协议为前提。
- 切换项目或 Agent 后，已有后台会话仍应按自身的可靠事件更新状态，不能把当前前台会话的状态复制给其他会话。
- 断线、程序重启或连接身份改变后，不沿用过期的运行／等待状态冒充实时事实。无法确认且没有其余可靠待处理事实的会话进入其他会话。
- 意外断线确实影响当前工作并需要用户恢复时，属于待处理；普通历史会话未连接，不自动制造错误或待处理事项。
- 不应仅为了侧栏分类而启动所有 Agent、全量恢复历史会话或持续高频查询状态。

## 8. 产品验收场景

以下是后续实现的验收要求，不表示本轮已经执行验证。

| 场景 | 预期结果 |
| --- | --- |
| 初次使用或已有用户升级 | 默认仍按项目组织 |
| 设置切换并再次启动 | 选择被记住；生效方式清楚，不静默打断运行中的工作 |
| 多个项目中的会话同时工作 | 分别正确归组，行内可识别项目，每个会话只出现一次 |
| 后台会话持续流式输出 | 留在进行中，显示进度图标，不因普通未读反复换组 |
| 后台回复结束且未读 | 进入待处理，显示带未读点的对话图标 |
| 最新回复实际显示在前台 | 没有其余待处理事项时进入其他会话，当前正文和选择保持不变 |
| 后台加载、窗口最小化或查看旧消息 | 未展示的最新回复仍保持未读 |
| 阅读与新回复同时发生 | 尚未展示的新内容不被本次已读清除 |
| 收到授权或提问，仅打开会话 | 仍处于待处理，并显示对应图标 |
| 完成授权或回答，Agent 继续工作 | 返回进行中；已失效请求不继续占据待处理 |
| 单个工具失败但 Agent 正在自行恢复 | 保持进行中，不凭单次工具失败制造用户待办 |
| 当前会话发生需用户介入的故障 | 进入待处理并显示警告图标；打开后有对应问题和可行操作 |
| 主动停止、新建或仅发现的历史会话 | 没有更高优先级事项时进入其他会话，不被标成已完成 |
| 切换会话或 Agent 后，后台完成或请求输入 | 状态归属原会话，不漏到当前会话，也不因切换而误清 |
| 快速点击、键盘导航与状态换组同时发生 | 不误选补位行，不重复激活，不抢焦点、不切错正文 |
| 分组折叠、空组或大量会话 | 数量正确，展开偏好被保留，会话仍可访问 |
| 不同主题、读屏和触控 | 图标可辨认，说明可获取，行内没有常驻原因文字 |
| 程序重启或连接失效 | 没有当前依据时不虚报运行或等待，也不擅自认定任务完成 |

## 9. 技术调研问题

这些问题由开发计划承接，本文不预先指定类、接口、存储结构或实现方案：

1. 如何复用现有会话状态链，可靠接收后台及跨 Agent 的运行、回复结束、交互请求与故障事实。
2. 如何判断最新回复已显示在前台，并避免同时到达的新内容被误清；跨窗口、重载与重启后的阅读状态如何处理。
3. 非正常结束、多个待处理原因并存时，如何得到一致的归组、图标选择与解除规则。
4. 设置是否可以直接生效，若需重载如何保持用户正在进行的工作。
5. 如何使用原生导航与图标，在换组、折叠、虚拟化和键盘操作时保持选择、焦点与阅读连续性。
6. 所需验证范围、平台差异与性能成本，以及哪些边界需要进一步产品确认。

本文作为产品需求基线；技术选型、实施阶段与子代理审查记录见开发计划。当前均未修改产品代码，不提交或推送。
